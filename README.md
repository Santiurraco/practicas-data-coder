¿Por qué es mala práctica usar SELECT * en producción? Usar SELECT * en producción degrada el rendimiento, rompe integraciones futuras y expone datos sensibles, por ejemplo en el caso del Rendimiento y costos traer todas las columnas obliga a la base de datos a leer más información del disco y transferirla por la red. En servicios en la nube (donde se cobra por datos escaneados, como BigQuery o Snowflake), esto aumenta directamente los costos operativos y vuelve más lentas las consultas.
Mantenibilidad (código frágil): Si alguien agrega, elimina o reordena columnas en la tabla original, una consulta con SELECT * cambiará su estructura de salida sin aviso. Esto suele romper aplicaciones, pipelines de datos o reportes que esperan un orden o cantidad fija de campos.
Seguridad y privacidad: Al seleccionar todo por defecto, es muy fácil arrastrar sin querer columnas confidenciales (como contraseñas encriptadas, tokens, DNI o datos bancarios) hacia reportes o interfaces donde los usuarios no deberían verlas.
Por su parte, utilizar alias AS es una buena práctica porque traducen nombres técnicos al lenguaje de negocio para evitar malentendidos, por ejemplo un alias para el campo total_amount se modifica usando SELECT total_amount AS monto_total y lo transforma en algo que cualquier persona del área de finanzas puede interpretar directamente.
